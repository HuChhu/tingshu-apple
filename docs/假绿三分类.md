# CI 假绿三分类（2026-11-22 团队教训沉淀）

> 共同根因：**"CI SUCCESS" 必须读到任务粒度才能下结论，build 级 SUCCESS 是假绿高发区。**

## ① 配置期污染（配置能过，构建意义全无）
- 案例：`android.aapt2FromMavenOverride=/usr/bin/aapt2` 本机 hack 入 git
- 症状：Gradle 配置阶段把 AGP 的 aapt2 换成不存在路径，Kotlin 目标静默不注册 → "Task not found"
- 教训：项目配置禁含本机绝对路径/hack，本机覆盖放 `~/.gradle/gradle.properties`
- 破获方式：逐任务读日志，不只看 BUILD 结果

## ② 插件不兼容导致任务被跳
- 案例：KMP 顶层 `application` 插件 + `withJava()` 缺失
- 症状：BUILD SUCCESSFUL 但 Kotlin 根本没编译（任务被 skip）
- 破获方式：检查产物文件是否真产出（.class/.klib 存在性断言）

## ③ 任务级 SKIPPED 的 build 级假 SUCCESS（最隐蔽）
- 案例：Linux 上 `linkReleaseFrameworkIosArm64`
- 症状：
  ```
  > Task :compileKotlinIosArm64                ← 真跑
  > Task :xcodeVersion SKIPPED                 ← K/N 检测无 Xcode
  > Task :linkReleaseFrameworkIosArm64 SKIPPED ← link 被跳过
  BUILD SUCCESSFUL in 1m 52s                   ← 零产物
  ```
- 破获方式：`grep "linkReleaseFrameworkIosArm64 SKIPPED" → exit 1`（已入 workflow）
- 教训：**静态闸（find/断言）根本轮不到执行**，必须先有 task-level 断言

## K/N 交叉编译能力矩阵（定谳）
| 级别 | Linux x86_64 | macOS | 产物 |
|---|---|---|---|
| compile（klib） | ✅ 可（需移植平台库） | ✅ | `shared-core.klib` 112KB |
| link（framework） | ❌ K/N 主动 SKIPPED | ✅ | `shared.framework` |

> 交叉编译 ≠ 跨平台链接。Apple 链接器随 macOS 发行包分发，Linux 上没有。
